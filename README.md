# URL Checker

URL Checker — полнофункциональное приложение для асинхронной проверки доступности HTTP- и HTTPS-адресов. Пользователь может создать задание из списка URL, наблюдать за ходом обработки и просматривать HTTP-коды, ошибки и итоговую статистику.

## Демо

Приложение опубликовано на Render:

[Открыть URL Checker](https://url-checker-ui.onrender.com)

Первое обращение к неактивному бекенду может выполняться дольше из-за холодного запуска бесплатного сервиса.

## Возможности и технологии

Основные возможности:

- создание заданий для проверки списка URL с помощью HTTP `HEAD`;
- асинхронная обработка нескольких заданий и адресов;
- отображение прогресса, HTTP-кодов, ошибок и статистики;
- периодическое обновление активного задания и защита от устаревших ответов;
- отмена задания с сохранением результатов уже начатых проверок;
- ограничения параллелизма, частоты создания и количества активных заданий;
- защита исходящих запросов от SSRF: проверка URL, DNS и IP-адресов, привязка соединения к проверенным адресам и контролируемые перенаправления.

Стек бекенда: `Node.js`, `NestJS`, `TypeScript`, `Undici`, `Vitest`.

Стек фронтенда: `React`, `Redux Toolkit`, `TypeScript`, `Vite`, `Vitest`.

## Локальный запуск

Требуются совместимая версия Node.js и npm. Бекенд и фронтенд запускаются в отдельных терминалах.

Установка и запуск бекенда:

```bash
cd backend
npm ci
npm run start:dev
```

Бекенд доступен по адресу `http://localhost:3000`. Он использует значения конфигурации по умолчанию, поэтому файл `.env` необязателен. При необходимости его можно создать из примера:

```bash
cd backend
cp .env.example .env
```

Для фронтенда требуется адрес API в `frontend/.env`:

```dotenv
VITE_API_BASE_URL=http://localhost:3000
```

Установка и запуск фронтенда:

```bash
cd frontend
npm ci
npm run dev
```

Приложение доступно по адресу `http://localhost:5173`.

### Запуск через Docker

Для запуска приложения в контейнерах необходимы Docker и Docker Compose. Все команды выполняются из корня проекта.

Сборка образов и запуск контейнеров:

```bash
docker compose up --detach --build --wait --wait-timeout 60
```

Проверка состояния контейнеров:

```bash
docker compose ps
```

После запуска приложение доступно по адресу [http://localhost:8080](http://localhost:8080).

Остановка контейнеров:

```bash
docker compose down
```

## Архитектура и ключевые решения

1. **Асинхронная обработка заданий.** Бекенд сразу возвращает идентификатор созданного задания, а проверки выполняются в фоновом процессе.
2. **Управление конкурентностью.** Для одного задания и всего приложения действуют отдельные ограничения количества одновременных HTTP-проверок.
3. **Корректная отмена.** Ещё не начатые проверки отменяются, а уже выполняющиеся завершаются и сохраняют результаты.
4. **Безопасные исходящие запросы.** Каждый адрес и перенаправление проходят повторную проверку; соединение использует проверенные DNS-адреса с сохранением TLS-проверки сертификата и SNI.
5. **Согласованность интерфейса.** Фронтенд периодически запрашивает состояние активного задания, останавливает предыдущие запросы при переключении и игнорирует устаревшие ответы.

## Развёртывание

Проект размещён на Render двумя сервисами из одного репозитория.

Бекенд разворачивается как Web Service:

- корневая директория — `backend`;
- проверка состояния — `/`;
- `PORT` предоставляется Render.

Команда сборки:

```bash
npm ci && npm run build
```

Команда запуска:

```bash
npm run start:prod
```

Основная переменная окружения бекенда:

```dotenv
FRONTEND_ORIGIN=https://url-checker-ui.onrender.com
```

Остальные параметры имеют проверяемые значения по умолчанию и при необходимости настраиваются через `backend/.env.example`.

Фронтенд разворачивается как Static Site:

- корневая директория — `frontend`;
- каталог результата сборки — `dist`.

Команда сборки:

```bash
npm ci && npm run build
```

Переменная окружения фронтенда задаётся до сборки:

```dotenv
VITE_API_BASE_URL=https://url-checker-d3ht.onrender.com
```

Для локального запуска в контейнерах в проекте также сохранены Dockerfile для обоих приложений и конфигурация Docker Compose.

## Ограничения

- Задания хранятся в оперативной памяти бекенда и теряются при его перезапуске.
- История ограничена 200 завершёнными заданиями; самые старые записи автоматически удаляются.
- Состояние не разделяется между несколькими экземплярами бекенда.
- Уже начатый HTTP-запрос не прерывается при отмене задания.
- Бесплатный сервис Render может останавливаться при отсутствии активности, поэтому первый запрос после простоя иногда выполняется дольше.
